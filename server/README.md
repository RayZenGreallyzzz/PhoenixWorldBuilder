# 🌐 Phoenix Server — переносимый фундамент (alpha 0.1)

**Один игровой протокол, разные места размещения:** собственный Windows/Linux/macOS PC, VPS/Docker, Cloudflare Tunnel или Cloudflare Workers + Durable Objects. Исходники полностью принадлежат разработчику.

Этот каталог — **тестовая сетeвая основа**, а не готовый публичный MMORPG-бэкенд. Работает: гостевой вход с ником, комнаты по имени мира, синхронизация позиций, проверка скорости и границ движения, чат в протоколе, импорт/экспорт серверного JSON, временные онлайн-«капсулы» игроков в PLAY. **Пока нет:** регистраций, постоянных игровых аккаунтов, сохранённых героев, античит-физики, серверного урона, инвентаря, синхронизации монстров/навыков или стабильности MMO под нагрузкой.

## Фундамент прямо в Android Builder

В разделе **🌐 СЕРВЕРЫ** приложение хранит до 20 независимых подключений к ПК, VPS или Cloudflare и может проверять протокол перед PLAY. Кнопки **«📤 Копия серверов»** и **«📥 Восстановить»** переносят публичные адреса и ID миров между телефонами в `Phoenix_Server_Connections.json`. Ключи, администраторские токены и пароли в этот файл никогда не записываются; импорт не включает автоподключение, а существующий выбор сервера сохраняется. Старые локальные профили `phoenix-server-profiles-v1` продолжают читаться.

Сервер отправляет перечень доступных возможностей в `hello.capabilities` (Phoenix protocol v1). Builder честно показывает, что **гостевые комнаты, движение и чат** работают, а **регистрация, сохранённые герои, серверный бой, синхронизация навыков и инвентаря** — ещё будущие модули. Это позволяет позже подключить авторизацию, не смешивая её с локальными строительными данными.

Серверное ПО находится **вне APK** и по-прежнему запускается на выбранном устройстве/хостинге. Встроенный в APK слой — это клиент, переносимые настройки и редактор публикации мира, а не постоянно работающий сетевой хостинг.

## На собственном компьютере

Нужен Node.js 20+. Открой терминал в каталоге `server`:

```bash
npm install
npm test
npm start
```

По умолчанию сервер слушает **127.0.0.1:8787**, так что без изменения настроек он недоступен из интернета и с другого телефона. Адрес комнаты — `ws://127.0.0.1:8787/ws/main`, а проверка сервера — `http://127.0.0.1:8787/health`.

Для теста в локальной сети можно указать `PHOENIX_HOST=0.0.0.0` и подключиться с Android к `ws://<IP_КОМПЬЮТЕРА>:8787`. **Открывая порт 8787, разрешай его только в доверенной домашней сети; не выставляй незащищённый `ws://` прямо в публичный интернет.** В PowerShell:

```powershell
cd server
$env:PHOENIX_HOST="0.0.0.0"
$env:PHOENIX_PORT="8787"
npm install
npm test
npm start
```

Для постоянного размещения можно использовать Docker. Собирается из каталога `server`:

```bash
docker build -t phoenix-server .
docker run --rm -p 127.0.0.1:8787:8787 \
 -e PHOENIX_ADMIN_TOKEN="<случайный_секрет_длиннее_24_символов>" \
 -v phoenix-worlds:/srv/phoenix/data phoenix-server
```

## Через Cloudflare Tunnel (сервер всё ещё на твоём ПК)

Запусти ПК-сервер на localhost, установи `cloudflared` и для короткого теста выполни:

```bash
cloudflared tunnel --url http://localhost:8787
```

Cloudflare выдаст временный домен `https://*.trycloudflare.com`: в Phoenix Builder укажи его как `wss://*.trycloudflare.com`. Это **временный тестовый адрес**, а не постоянная инфраструктура. Для постоянного домена создай управляемый Tunnel и DNS-маршрут по инструкции Cloudflare. Настоящий компьютер должен продолжать работать.

Документация: https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/

## В Cloudflare Workers + Durable Objects

**Это альтернативный адаптер того же протокола, а не перенос бинарного Node.js-процесса**. Нужны аккаунт Cloudflare, установленный Wrangler и доступные по тарифу лимиты. В каталоге `server/cloudflare`:

```bash
npx wrangler login
npx wrangler secret put PHOENIX_ADMIN_TOKEN
npx wrangler deploy
```

Секрет задай **уникальный, 24+ символов**, сохраняй его у себя и не размещай ни в Builder, ни в APK, ни в GitHub. `wrangler.toml` задаёт SQLite-backed Durable Object, отдельный для каждого world ID. Cloudflare Workers Free поддерживает SQLite-backed Durable Objects с лимитами; смотри актуальные цены и квоты.

Документация: https://developers.cloudflare.com/durable-objects/ и https://developers.cloudflare.com/workers/wrangler/

## На Android

В следующей сборке Phoenix Engine, содержащей сетевой модуль, открой **🌐 СЕРВЕРЫ**:

1. Введи имя, адрес `ws://IP:8787` (домашняя сеть) или `wss://game.example.com`, ID мира (`main`) и ник.
2. Нажми **💾 Сохранить подключение**, потом **🧪 Проверить сервер**.
3. Чтобы публиковать карту, нажми **📦 Экспортировать мир для сервера** и сохрани `PhoenixServer_main_rev1.json`.
4. **Выключи PLAY перед публикацией.** Отправь JSON на свой сервер по административному HTTP API (пример ниже).
5. Включи галочку **«Подключаться при PLAY»**, потом нажми PLAY. Два Android-клиента увидят друг друга в одной комнате как временные тестовые модели.

**Важно:** экспорт серверного JSON пока содержит игровые определения и координаты, но **не содержит GLB, иконки и текстуры**. В онлайн-клиенте должны находиться соответствующие модели и мир. Не ожидай, что один серверный JSON автоматически загрузит всю карту на другой телефон: потребуется отдельно организовать публикацию игровых ресурсов.

## Импорт и перенос мира между серверами

Администратор задаёт `PHOENIX_ADMIN_TOKEN` через окружение Node-сервера или Cloudflare secrets. Если ключ короче 24 символов, административный API отключён.

```bash
curl -X PUT "http://127.0.0.1:8787/admin/world/main" \
  -H "Authorization: Bearer <СЕКРЕТ_ТОЛЬКО_НА_СЕРВЕРЕ>" \
  -H "Content-Type: application/json" \
  --data-binary "@PhoenixServer_main_rev1.json"

# Получить установленный мир, чтобы перенести на другой сервер:
curl "http://127.0.0.1:8787/admin/world/main" \
  -H "Authorization: Bearer <СЕКРЕТ_ТОЛЬКО_НА_СЕРВЕРЕ>" \
  -o PhoenixServer_world_backup.json
```

Останови/отключи игроков прежде чем менять опубликованную карту. При импорте предыдущая ревизия не может быть заменена более старой. Данные хранятся в `server/data/main.json` для Node или в Durable Object storage для Cloudflare. Для переноса на другой хост загрузи **тот же переносимый JSON**, сменив только DNS/адрес в настройках клиента. Данные аккаунтов и персонажей пока не создаются, поэтому переносить их ещё нечего.

## Почему так

```
Phoenix Builder (общий холст, GLB, мир, моб, навыки)
    └── export → Phoenix Server World JSON (версия формата)
                       ├── Node.js + ws     → PC / VPS / Docker
                       └── Cloudflare DO    → Workers / edge
Phoenix Game / Android (PLAY)
    └── WebSocket v1 → host/ws/<world-id>
          └── guest join / move / chat / players / reconnect
```

Общие модули `shared/protocol.mjs`, `shared/world.mjs`, `shared/room.mjs` не зависят от провайдера. Никогда не посылай на сервер авторитетные значения XP, урона или инвентаря от клиента: позднее эти действия будут вычисляться сервером с настоящей проверкой коллизий и скоростей. Регистрация, база аккаунтов, авторизация, команды, квесты, экономика и долговременное состояние будут **отдельными модулями**, подключаемыми к этому фундаменту.

**Ветка проекта:** `phoenix-engine-0.1`. Не хранить секреты, токены, ключи подписи или пароли в репозитории.
