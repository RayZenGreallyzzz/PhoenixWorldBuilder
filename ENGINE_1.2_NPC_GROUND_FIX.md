# Phoenix Engine 1.2 — исправление проваливания мобов GLB под землю

## Симптом

При импорте анимированного GLB через **🧬 МОБЫ / NPC** моб может
появиться на сцене по пояс в земле, а после анимации Attack/Hit
«уехать» ещё глубже. Скелетная анимация здесь не является проблемой
сама по себе: у некоторых моделей **центр GLB расположен у пояса**,
а клипы дополнительно двигают корневой узел модели по оси Y.

## Причина в коде старой версии

`PrefabEditor.attach()` раньше непосредственно ставил GLB-root в
`transform.position` на уровне земли, не учитывая минимальную
высоту вершин (положение ступней).

Кроме того, `PhoenixAnimations.Controller` получал тот же root
как объект игрового моба. В результате анимация, содержащая
`.position`-трек, могла изменить координаты визуальной модели
и временно увести ноги под землю.

## Исправление

- **Разделены два трансформа**: неподвижный относительно анимаций
  `render.root` для ИИ/коллизии/боёв/сохранения координат и отдельный
  `render.visual` для анимированного GLB.
- Добавлена отдельная группа **`render.anchor`**, которая компенсирует
  высоту подошв модели, не изменяя сохранённые координаты.
- Первоначальная высота рассчитывается по реальным вершинам
  SkinnedMesh с учётом скелета с помощью существующего
  `AvatarFit.measure()`, а не по грубому Box3 в bind pose.
- Во время PLAY положение опоры периодически обновляется по
  текущей позе, чтобы компенсировать корневое смещение в анимациях
  Idle/Walk/Attack/Hit. Исправление сглаживается, дорогие измерения
  выполняются не чаще раза в 0.35 секунды с ограниченной выборкой
  около 1500 вершин на персонажа.
- При возвращении в EDIT высота пересчитывается заново, а
  сохранённый JSON-формат и трансформы мобов **не меняются**.
- Новая загрузка и существующие мобы из старых JSON-проектов
  используют одну и ту же исправленную логику `attach()`.

## Важная деталь для пользователя

На скриншоте счётчик показывает **«Шаблонов: 1 · На сцене: 1»**
при пяти видимых персонажах. Это значит, что в игровом слое
находится **только один** экземпляр моба. Другие персонажи
возможно размещены Builder как обычные строительные модели и
не будут самостоятельно использовать игровой ИИ. Исправление
опоры применяется к игровым мобам, но не изменяет обычные
строительные объекты.

Чтобы добавить остальных мобов с ИИ: в EDIT открыть **МОБЫ / NPC**,
выбрать шаблон, **Поставить моба**, коснуться земли. Убедиться,
что счётчик «На сцене» увеличился. Затем запустить PLAY.

## Регрессионный тест

`tests/test-prefab-editor.cjs` создаёт тестовую GLB-модель,
у которой геометрия симметрична относительно центральной точки
(низ коробки на Y=-1). Затем проигрывает Attack с анимированным
корневым треком Y=-0.9.

Проверяется:
1. В EDIT ступни стоят на Y=0, хотя исходный GLB-root был
   расположен относительно центра тела.
2. Mixer анимирует только `render.visual`, не игровой `render.root`.
3. После Attack ступни не уходят под землю.
4. Трансформ игрового объекта в JSON остаётся без изменений.
5. При выходе в EDIT высота снова корректна.

## Android

Версия 1.2.0 (`versionCode=12`), постоянный package ID
`com.phoenix.worldbuilder.engine.stable`. Для обновления без
потери данных требуется та же подпись, что и в предыдущих версиях.

**Важное ограничение текущей библиотеки UV44:** встроенные GLB
загружаются из `assets/pwb/` внутри APK. При замене APK
Android не оставляет этот каталог из старой версии.
Поэтому, до реализации специального выноса модулей в
постоянное хранилище, безопасный полнофункциональный APK
по-прежнему должен содержать эти встроенные модели.

Автоматические тесты подтверждают кодовую логику; реальное
поведение GLB на пользовательском Android нужно проверить на устройстве.
