# Phoenix Engine — техническая основа 0.1

## Зафиксированное направление

**Главная платформа разработки и редактора — Android.** Игры должны
проектироваться с возможностью дальнейшего запуска на Linux. На данном этапе
отдельный редактор для Linux не разрабатывается.

Игровые направления: **3D и 2.5D**, с расширяемыми компонентами для RPG,
MMORPG, шутеров и MOBA. Полноценные сетевые серверы и игры этих жанров пока
не реализованы; закладываем совместимые форматы и разделение runtime/редактора.

## Точка старта

- Репозиторий: `RayZenGreallyzzz/PhoenixWorldBuilder`.
- Проверенная основа WebView: `stable/uv44` — восстановленная версия UV44
  с выборочным переносом исправлений UV и углов.
- Рабочая ветка движка: `phoenix-engine-0.1`, создана от `stable/uv44`.
- Исходная ветка `main` не изменялась.
- Есть успешная тестовая сборка Android:
  https://github.com/RayZenGreallyzzz/PhoenixWorldBuilder/actions/runs/44822331653
- Ограничения той сборки: в публичную ветку не загружена встроенная
  библиотека GLB из APK; Android-оболочка требует проверки; запуск на
  настоящем Android и стабильные FPS ещё не подтверждены.

## То, что уже делает Builder

- Строительство, материалы и сцены.
- GLB-импорт и работа с персонажем.
- Перемещение персонажа в режиме строительства; Idle/Walk.
- Сохранение/загрузка проектов, GLB-экспорт.
- UI и управление на Android.

Не дублировать эти системы без доказанной необходимости. Движок должен
использовать их через адаптеры.

## Архитектурные границы

1. `Builder/Editor` — инструменты редактирования, не выполняют игровую
   логику, когда не требуется.
2. `Phoenix Core` — идентификаторы сущностей, компоненты, события,
   состояние мира и режимы. **Без зависимости от Android/Three.js**.
3. `Phoenix Runtime` — физика, анимации, ИИ и игровые правила; запускать
   только при необходимости.
4. `Android Platform` — сенсорный ввод, файлы, APK и родные API.
5. `Linux Platform` — запланированная оболочка для запуска игр и
   серверных приложений; API предусмотреть заранее.
6. `Game Project` — переносимые данные: мир, ссылки на ресурсы,
   сущности, компоненты, игровые настройки. Не сохранять системные пути Android.

Режимы редактора: `edit` (строительство), `play` (игра),
`live-edit` (редактирование при игре). Третий режим является
**архитектурным планом**, не готовой функцией интерфейса.

## Визуальное создание игр без кода

Планируются:
- `Phoenix Asset Manager` для GLB (собственные 311 моделей, 18 с анимациями).
- `Prefab Editor`: характеристики, компоненты, оружие, поведение мобов.
- Размещение мобов прямо на локации пальцем.
- `UI Editor` для HP/MP, джойстиков, кнопок атак и навыков.
- `Skill Editor`: изображение, урон, расход MP, перезарядка, эффект.
- `Animation Controller`: назначение Idle, Walk, Run, Attack, Hit, Death
  при наличии соответствующих анимаций в GLB.
- Игровые шаблоны RPG / MMORPG / Shooter / MOBA на общем ядре.

**Отдельный ретаргетер анимаций не интегрируем в Phoenix Engine.**
В движок импортируем готовые GLB с подготовленными анимациями.

## Обязательные правила производительности

- Никаких дополнительных циклов `requestAnimationFrame` на каждую подсистему.
- Не сериализовать неизменённые большие данные при каждом действии Builder.
- Загрузка моделей и текстур по требованию, освобождение ресурсов.
- Во время строительства не запускать игровой ИИ/физику.
- При импорте/загрузке крупных проектов не блокировать надолго кадр.
- Иметь замеры времени работы функций, а не исправлять лаги наугад.

## Первое техническое достижение

Минимальный модуль `engine/core/phoenix-core.js` хранит игровые сущности,
компоненты и режимы независимо от редактора. Он **не подключён к Builder**
и не запускает циклов. Перед добавлением реального `PLAY` его нужно
проверить тестами и затем внедрять через отдельный адаптер.

**Первый интерактивный критерий:** построить дом в Builder →
добавить игровую сущность → нажать PLAY → ходить внутри дома →
вернуться в EDIT без изменения или повреждения строительного проекта.
